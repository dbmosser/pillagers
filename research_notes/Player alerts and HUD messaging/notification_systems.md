# Notification systems: priority, queueing, rate limiting, merging, interruption and lifetime of HUD messages and announcer lines

Research date: 2026-10-27. Method: web search and page fetches. Several primary sources could not be read: GDC Vault talk pages are behind a login, and the Valve Developer Community wiki, the BeyondUnreal wiki and the Audiokinetic blog returned HTTP 403 to the fetch tool. Where a fact comes from a search-result summary rather than an opened page, it is marked "(search summary)". Years marked "n.d." could not be confirmed. Everything under "Inferences" is my own reasoning, not a sourced fact.

Overall picture: AAA studios rarely publish their notification-manager tables. The best public, concrete specification of a HUD message queue is Epic's Fortnite Creative HUD Message Device, which exposes the engine-level model (layers, numeric priority, preempt-and-requeue, queue timeout, repeat behaviour, default 5 s lifetime). Audio and dialogue arbitration is best documented by Blizzard (Overwatch threat-scored mix, GDC 2016) and Valve (rule-based dialogue with repetition flags, GDC 2012). Merging and throttling numbers are best documented by World of Warcraft combat-text addons, not by Blizzard itself.

## 1. Documented priority schemes: how message classes are ranked, what interrupts what, what is dropped vs queued vs merged

### Takeaway
The documented model is channel-based: each screen region (layer) shows one message at a time, a higher-priority message preempts the current one and pushes it back into the queue, an "immediate" class bypasses everything, and anything that cannot show within its queue timeout is dropped (Fortnite's default is to not queue at all). For audio, Overwatch ranks sounds by live threat to the listener rather than by a fixed class table. No AAA shooter publicly documents a full class ladder (danger, objective, social, reward, system); that ladder has to be designed.

### Cited Findings
- Fortnite HUD Message Device: "Only one message at a time will display on a layer, and any other messages set to that layer will be queued." Different layers can show at the same time. Layer default is 0. ([Epic Developer Docs, Using HUD Message Devices in Fortnite Creative, current page read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Fortnite priority: default 5; "Messages with a lower number (such as 1) are a higher priority, and will move any displayed message on the same layer to a queue." So a preempted message is requeued, not destroyed. A "Display Immediately" setting means "the message will display immediately and ignore any other messages." ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Fortnite also separates presentation tiers: a "HUD Widget" choice of Basic or Critical, a default sound "Message - Important", and fixed placements Bottom Center, Top Center, Center Right or Custom (9 anchors plus pixel offsets). ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Overwatch's audio goal "Play by Sound" was set by the game director early in production; the GDC 2016 talk by Scott Lawlor and Tomas Neumann (Blizzard) says many systems affected all of music, SFX and dialog to reach it. ([GDC Vault, Overwatch: The Elusive Goal: Play by Sound, 2016](https://gdcvault.com/play/1023010/Overwatch-The-Elusive-Goal-Play))
- Overwatch's audio pillars were Hero VO, a clear mix, pinpoint accuracy, gameplay information, and a "Pavlovian response"; priorities, obstruction, occlusion and reverbs were set per event in Blizzard's editor (TED). (search summary of [Audiokinetic, Wwise Tour 2016: Blizzard Overwatch, Audio in Overwatch, 2016](https://www.audiokinetic.com/learn/videos/fGDOgn2WXLs))
- Overwatch threat scoring: each enemy player got an "importance" in the mix; enemies aiming at you were more threatening than nearby enemies not looking at you, which "would receive less 'threat points' and be lower in the mix." Raw distance failed (an enemy on a ledge above with no quick path still read as close), so the team measured the length of the enemy's path to the listener, borrowed from flight-path AI work. Result: enemy footsteps and battle sounds are muffled from hiding spots and grow clearer as enemies approach. ([PCGamesN, Overwatch devs on creating a game you can play by sound, 2016-03-18](https://pcgamesn.com/overwatch/overwatch-devs-on-creating-a-game-you-can-play-by-sound-and-announcing-dolby-atmos-support))
- Valve's dialogue system (Left 4 Dead, Team Fortress 2 era): lines are chosen by matching rules against many tracked world facts so characters remember history; the most specific matching rule wins and less specific rules are fallbacks; it was built so writers can add lots of content and lines can be interrupted sensibly. ([GDC Vault abstract, Elan Ruskin, AI-driven Dynamic Dialog through Fuzzy Pattern Matching, 2012](https://www.gdcvault.com/play/1015528/AI-driven-Dynamic-Dialog-through); [Emily Short, GDC 2012 talk on dynamic dialogue, 2012-03-16](https://emshort.blog/2012/03/16/gdc-2012-talk-on-dynamic-dialogue/); [Robert Yang, Rule databases for contextual dialog and game logic, 2012-07](https://www.blog.radiator.debacle.us/2012/07/rule-databases-for-contextual-narrative.html?m=1))
- Pixel Crushers Dialogue System for Unity (a widely used middleware): an NPC will not bark if it is already speaking a higher-priority line. (search summary of [Pixel Crushers manual, How to Play Barks, n.d.](https://www.pixelcrushers.com/dialogue_system/manual/html/how_to_play_barks.html))
- Halo Infinite sorts medals into six areas (Killing Spree, Mode-specific, Multikill, Proficiency, Skill, Style) and four difficulty tiers. ([Game Rant, Halo Infinite: Every Mythic Medal, n.d.](https://gamerant.com/halo-infinite-mythic-medals/)) How these categories arbitrate the announcer queue is not documented; one Halo 4 player reported that the killing-spree callout seemed to take priority over "Killionaire" (fan anecdote, unverified). ([se7ensins forum, Halo 4 multi-kill medals, n.d.](https://www.se7ensins.com/forums/threads/halo-4-multi-kill-medals.806227/))
- Generic HUD guidance (secondary blogs, not studio sources): a four-tier hierarchy critical, important, informational, ambient, each with less visual weight; persistent information in corners, momentary information near the centre. ([StraySpark, Game UI/UX Design Principles, n.d.](https://www.strayspark.studio/blog/game-ui-ux-design-principles)) Clutter comes from missing priority rather than element count; contextual information should fade once it has served its purpose. ([Argentics, Game HUD Design, n.d.](https://www.argentics.io/game-hud-design))
- A HUD ranking table: Critical (health, ammunition), High (minimap), Medium (active objectives), Low (experience and progression, "Appears on gain, auto-hides"), Variable (contextual prompts, "Only when action available"). ([Generalist Programmer, Game UI/UX Design: Complete Guide, 2025-10-03](https://generalistprogrammer.com/game-ui-ux-design))
- Open-source example (hobby racing-game project): a notification queue with five priority levels, three visible at once, higher urgency preempting lower, filtering by a player-chosen notification level, and a dismiss action. (search summary of [GitHub, 47PADO47/nfs-mw PR #231, HUD events and the notification queue, n.d.](https://github.com/47PADO47/nfs-mw/pull/231))
- Patent prior art on the queue mechanics: insert each item by priority, play the head, relocate items when their priority changes ([USPTO 6738742](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/6738742); [USPTO 6542868](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/6542868)); high-priority messages go to the head of the queue, normal ones go after the highest-priority message not yet shown ([USPTO 7221331](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7221331)). (search summaries; patent years not confirmed)

### Inferences
- The sourced model gives four outcomes per incoming message, and every message type should declare which one it uses: (a) bypass and show now (Fortnite "Display Immediately"), (b) preempt and requeue the current one (lower priority number on the same layer), (c) queue with a timeout, (d) drop (Fortnite default "Don't Queue"). A fifth, merge into the showing message, comes from section 2.
- Channels (layers) matter more than one global priority. A shooter typically needs separate channels for: centre danger banner, objective banner, kill or event feed, pickup feed, announcer voice, squad voice barks, and tutorial hint. A danger banner should never wait behind a loot line because they never share a channel.
- Suggested class ladder for a real-time extraction shooter (my design, not sourced): P0 critical danger to you or a teammate (downed teammate, being hunted, extraction closing) shows immediately and may preempt anything; P1 objective state changes; P2 squad and social; P3 reward and loot; P4 system and tutorial. P3 and P4 never preempt; P0 preempts P1 to P4 and requeues P1 only.
- Overwatch's approach suggests the announcer and bark priority can be dynamic: score a line by live threat or relevance at the moment it would play (aiming at you, path length, distance), not only by its static class.

### Gaps
- No public primary source found for: Overwatch's actual VO priority values or interrupt rules (the GDC Vault video is login-gated and the Audiokinetic blog returned 403); Destiny 2's notification queue; Call of Duty medal and score popup arbitration; Fortnite and Apex pickup and XP feed internals; Halo announcer queue logic; Final Fantasy XIV flytext priority.
- Unreal Tournament 2004's announcer queue class (AnnouncerQueueManager) appears to be an inspectable open example, but the BeyondUnreal wiki page returned 403, so its priority enum and gap timing could not be verified here.

## 2. Rate limiting and dedup: merging repeats, per-type cooldowns, max per window, combat suppression, batching rewards

### Takeaway
The documented tools are: one instance per source (no stacking duplicates), "repeat resets the timer" instead of re-showing, merge windows that fold rapid identical events into one line with a count or total, per-line speak-once and respeak-delay flags, and a global gap plus a longer per-speaker gap for barks. Batching rewards until a calm moment is common practice but I found no studio source that documents it.

### Cited Findings
- Fortnite dedup: "Allow Multiple in Queue" is Off by default, meaning a device's message is queued only if that device has no message already queued or displayed. "Show Behavior If Showing" defaults to "Reset Display Time" (alternatives: Replay, Ignore), so a repeat of a message already on screen extends it instead of stacking a second copy. ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Fortnite staleness check: "Re-Evaluate Messages On Show" (default Off) re-checks a queued message when it is about to show. ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Valve Source response system syntax includes per-response options "speakonce", "respeakdelay" (with an interval), "delay" and "odds", and per-group options "permitrepeats", "sequential" and "norepeat". (search summary of [Valve Developer Community wiki, Response, n.d.](https://developer.valvesoftware.com/wiki/Response); the page itself returned 403, so exact semantics and defaults are not verified)
- WoW combat text addons (Blizzard's own throttling is not documented): MikScrollingBattleText can "Merge AoE data into one event with cumulative damage/healing done with number of normal and crits specified" and has spam filters ([CurseForge, MikScrollingBattleText, n.d.](https://www.curseforge.com/wow/addons/mik-scrolling-battle-text)); its TBC Anniversary changelog 5.2.1 (August 2026) makes spam thresholds adjustable in steps of 50 for heal and damage and 25 for power (search summary of [CurseForge, MSBT TBC Anniversary files, 2026](https://www.curseforge.com/wow/addons/mikscrollingbattletext-tbc-anniversary/files/7573274)).
- xCT+ has a spam merger that combines rapid hits from the same spell into one message and groups AoE events into a couple of totals ([CurseForge, xCT+ Combat Text, n.d.](https://www.curseforge.com/wow/addons/xct-plus)); Splatter Combat Text groups rapid hits into one number with a count, for example "8.4K x5" ([CurseForge, Splatter Combat Text, n.d.](https://www.curseforge.com/wow/addons/splattercombattext)); ZSBT advertises merge, throttle and threshold controls ([CurseForge, Zore's Scrolling Battle Text, n.d.](https://www.curseforge.com/wow/addons/zores-scrolling-battle-text)). (all search summaries)
- WoW Patch 12.0 closed COMBAT_LOG_EVENT_UNFILTERED to addons, and most floating combat text addons stopped working, so those merge features now depend on what Blizzard still exposes. (search summary of [CurseForge, nugsCombatText, 2026](https://www.curseforge.com/wow/addons/nugscombattext))
- Halo 3 multikill medals use a 4 second window between kills, escalating from Double Kill up to Killionaire (10 kills each within 4 s of the last), which collapses a burst of kill events into one escalating callout. ([Halo Fandom wiki, Halo 3 medals, n.d.](https://halo.fandom.com/wiki/Halo_3_medals))
- Bark repetition control: cooldown timers, priority systems and contextual filtering are the main tools against one line becoming a meme through overuse; Skyrim's guard barks are the cautionary example. ([Gamemaxxing, Bark Systems, n.d.](https://gamemaxxing.baes.so/concept/bark-systems)) Pixel Crushers' "Bark On Idle" uses a min and max interval between barks. ([Pixel Crushers manual, Bark On Idle, n.d.](https://www.pixelcrushers.com/dialogue_system/manual2x/html/bark_on_idle.html))
- An indie design spec for hero barks uses a short global gap between any two barks, a longer per-character gap, a no-repeat window and priority levels; high-priority barks skip the per-character gap but still respect the global gap. (search summary of [GitHub, Sluborg/Godblooded PR #158, barks spec, n.d.](https://github.com/Sluborg/Godblooded/pull/158) and [PR #175, bark tempo](https://github.com/Sluborg/Godblooded/pull/175); a small-project spec, not an authority)
- Anti-pattern from a System Shock 2 VR port: the original HUD message funnel played a sound on every message with no rate limiting, dedup or priority gating; the proposed fix is one central queue with per-message lifetimes, and the alert sound fired once centrally when a message is posted, not by each caller. ([GitHub, tommy-xr/shock2quest issue #916, n.d.](https://github.com/tommy-xr/shock2quest/issues/916))
- Combat suppression: "during intense combat, only critical data like health and ammunition should be visible." ([Generalist Programmer, 2025-10-03](https://generalistprogrammer.com/game-ui-ux-design))

### Inferences
- Dedup key: (message type, subject). A second event with the same key while the first is visible should merge into it (update count or total, reset its timer, as Fortnite does) rather than queue a second line. While queued, a duplicate should replace the queued copy, not add one.
- Merge windows by kind (my proposal, scaled from the sources): damage or hit text about 0.3 to 1 s; kill and pickup chains about 3 to 4 s (Halo's 4 s chain window); money or score gains can roll into one running total until the player is out of combat.
- Every sound-carrying message type needs a per-type cooldown plus one global gap, so audio cannot stack even when text merges; the shock2quest fix says the sound should fire from the central manager only.
- Combat suppression rule: while "in combat" (recent shot fired, damage taken, or enemy aware), hold P3 and P4 in a deferred bucket that merges, then flush it as one summary line when combat has been quiet for a few seconds or at extraction or end of match. This is the batching rule the brief asks about; it is an inference, not a sourced studio practice.
- A hard cap on visible lines per channel (the hobby example uses 3) and a cap on new lines per second per channel prevents feed floods; overflow merges or drops the lowest-priority oldest item.

### Gaps
- No studio source found for: per-type cooldown values in any AAA shooter; a documented "max N messages per T seconds" limit; documented batching of rewards to end of fight or end of match (for example CoD's after-action screens or Destiny's post-game reward flow); Blizzard's built-in floating combat text merging; FFXIV flytext throttling.
- MSBT's exact merge interval and xCT+'s default merge interval could not be confirmed (CurseForge pages were seen only through search summaries).
- Valve response flags: semantics and default values (for example respeakdelay units) not verified because the wiki returned 403.

## 3. Lifetimes: display durations per class, fade times, how long a queued message may wait

### Takeaway
The firmest numbers come from Fortnite (5 s default lifetime, queued messages dropped by default) and from subtitle accessibility practice (at least 1 s per line, at least 2.5 s per full subtitle, about 15 characters per second reading speed, player-adjustable duration). Popup animation is commonly 200 to 300 ms. I found no published per-class lifetime tables or staleness timeouts from a AAA shooter.

### Cited Findings
- Fortnite HUD message "Display Time" default 5 seconds (or Permanent, or custom); "Queue Timeout" default "Don't Queue", meaning a message that cannot show right away is not kept; a custom timeout "determines how long the message remains in the queue"; intro and outro animations default None, with Fade, Zoom, Slide and Bounce options; "Time From Round Start" default 10 s for round-start messages. ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))
- Subtitle timing (Ian Hamilton, accessibility consultant): "Each line of text must be displayed for at least one second, whereas a full subtitle must remain on the screen for a minimum of two and a half seconds." (search summary of [Canada Media Fund, Subtitles in Video Games: The Best Practices, n.d.](https://cmf-fmc.ca/now-next/articles/subtitles-in-video-games-the-best-practices/))
- QA rule of thumb of about 15 characters per second for caption timing; lines in rapid back-and-forth dialogue pile up faster than people can read if each line shows only for its audio length. (search summary of [Bugnet, QA testing for subtitle and caption display, n.d.](https://bugnet.io/blog/qa-testing-for-subtitle-and-caption-display))
- A subtitle duration setting helps younger players, players with visual impairments and anyone who needs more reading time. (search summary of [Kodeco, Improving Accessibility in Unity Games Part 2, n.d.](https://kodeco.com/5783534-improving-accessibility-in-unity-games-part-2?page=5)) Xbox Accessibility Guideline 104 recommends a larger minimum default text size for subtitles because they are on screen only briefly. (search summary of [Microsoft, Xbox Accessibility Guidelines version history, n.d.](https://learn.microsoft.com/ar-sa/xbox/accessibility/xag-version-history))
- Animation timing: notification popups 200 to 300 ms with bounce or elastic easing; general UI animation "typically 200-400ms"; active objectives "Fades after being read" (no time given); experience gains "Appears on gain, auto-hides." ([Generalist Programmer, 2025-10-03](https://generalistprogrammer.com/game-ui-ux-design))
- Combo window as a lifetime: Halo 3's 4 s gap between kills defines how long a multikill chain stays open. ([Halo Fandom wiki, n.d.](https://halo.fandom.com/wiki/Halo_3_medals))

### Inferences
- Lifetime by reading load, not by class alone: show time = max(class minimum, 1 s + characters / 15), capped (my proposal: 2.5 s floor for anything with words, about 6 s cap for transient lines, Fortnite's 5 s as the default). Very short callouts of two or three words can sit near the floor; a merged line that updates should reset to at least its floor.
- Queue staleness should be short for anything tied to a moment: combat and kill callouts lose meaning in about 1 to 2 s and should drop; objective changes can wait several seconds but must re-check that they are still true when shown (Fortnite's "Re-Evaluate Messages On Show"); rewards should not queue at all but merge into the deferred summary from section 2.
- Fade in about 150 to 250 ms, fade out about 300 to 500 ms is consistent with the 200 to 400 ms animation guidance; this split is my inference, not a sourced number.
- A player setting for message duration (or a global text-speed multiplier) is the accessibility norm for subtitles and transfers directly to HUD callouts.

### Gaps
- No published per-class durations (danger vs objective vs reward) from Overwatch, Apex, Fortnite Battle Royale, CoD, Destiny 2 or Halo.
- No published queue-wait (staleness) timeouts from any AAA game; Fortnite does not say what happens to a message when its custom queue timeout expires (presumably discarded).
- Primary XAG 104 text and the original Ian Hamilton source were not opened.

## 4. Tutorials and first-time hints: gating (once per player, context triggered, never during combat)

### Takeaway
The sourced practice is: prompts appear in context only when the action is available, tutorials stay revisitable, features unlock progressively, and high-pressure moments are bad for teaching. A very recent example (Call of Duty: Modern Warfare 4 launch patch, October 2026) cut the number of guide-character notifications and moved its tutorials. A sourced "never during combat" rule was not found; it is a reasonable inference.

### Cited Findings
- Contextual prompts appear "Center-screen or near interaction" and only "when action available"; tutorials should be "comprehensive tutorials that can be revisited at any time"; advanced features are introduced progressively as players develop mastery. ([Generalist Programmer, 2025-10-03](https://generalistprogrammer.com/game-ui-ux-design))
- High-intensity moments make players less receptive to new information. (search summary of [UX Collective, The UX of video game tutorials, n.d.](https://uxdesign.cc/the-ux-of-video-game-tutorials-7e7bc37e2ceb))
- A "don't show again" option gives hand-holding the first time and lets play speed up once the player decides they do not need it. (search summary of [GameDev.net forum thread, n.d.](https://gamedev.net/forums/topic/694033-turn-based-action-selection-and-ui-design/))
- Call of Duty: Modern Warfare 4 launch patch notes, UI and UX: "Reduced the notifications you get about Gunny" and "Improved the positioning of Gunny tutorials" (Gunny is the game's guide character). ([Insider Gaming, Modern Warfare 4 launch patch notes explained, 2026-10-22](https://insider-gaming.com/modern-warfare-4-launch-patch-notes-explained/))
- Fortnite's "Queue Message for Join In Progress Players" (default On, respects Queue Timeout) shows that onboarding text for late joiners is handled as a queued class rather than shown on top of play. ([Epic Developer Docs, n.d., read 2026-10](https://dev.epicgames.com/documentation/en-us/fortnite/using-hud-message-devices-in-fortnite-creative))

### Inferences
- Gate every hint on four checks: not seen before (per player profile, persistent), the action is available right now (context trigger), the player is not in combat or in a P0 or P1 state, and a hint budget per raid or session is not used up. Hints that fail the combat check should wait in the deferred bucket with a long staleness timeout and be dropped if the context is gone when calm returns.
- Prefer failure-triggered hints for advanced mechanics (show "hold to crouch" only after the player is spotted standing several times) over time-triggered ones; this follows from the receptiveness point but is not a sourced rule.
- Hints should mark as seen when the player performs the action, not only when the hint is shown, so a player who already knows the mechanic never sees it.

### Gaps
- I found no studio source that states "never show tutorials during combat" as a rule, and no published per-session hint budget numbers. A secondary search summary mentioned a "per-session hint budget tuned during playtesting" but I could not confirm which page said it, so it is not cited above.
- A patent on failure-triggered tutorials was surfaced by search but not opened; its number and claims are unverified.
- No sourced data on how Apex, Fortnite or Destiny 2 gate their first-time tips.

## 5. Moving information out of text: world markers, pings, sound, icons, rumble; when text is the right tool

### Takeaway
The strongest documented cases are Overwatch, which set "Play by Sound" as a design goal and encoded threat into the mix, and Apex Legends, whose contextual ping system was tested with voice chat banned internally and is widely credited with replacing much voice and text communication. Text remains the tool for things that have no place in the world or need exact words (numbers, names, rules), and even then it should be short and paired with a sound or icon.

### Cited Findings
- Overwatch: every hero has a unique footstep sound, which Lawlor called an important cue; threat is carried by mix level and muffling (path-length based) rather than by HUD text, telling the player whether they are safe or being approached. ([PCGamesN, 2016-03-18](https://pcgamesn.com/overwatch/overwatch-devs-on-creating-a-game-you-can-play-by-sound-and-announcing-dolby-atmos-support))
- Overwatch "gameplay information" and "Pavlovian response" were explicit audio pillars, meaning sounds were designed to be learned as signals. (search summary of [Audiokinetic, Wwise Tour 2016](https://www.audiokinetic.com/learn/videos/fGDOgn2WXLs))
- Apex Legends: Respawn banned voice communication during internal testing of the ping system and used fake names to mimic playing with strangers. (search summary of [GameRevolution, Apex Legends ping system, n.d., likely 2019](https://www.gamerevolution.com/?p=493241))
- Apex's ping builds on Battlefield's "press Q to mark enemy" and adds context-sensitive voice lines; one press can mark a location, a building or a weapon on the floor. (search summary of [PC Gamer, Apex Legends' ping system is a tiny miracle, 2019](https://www.pcgamer.com/au/apex-legends-ping-system-is-a-tiny-miracle-for-fps-teamwork-and-communication/)) Fortnite copied the system in Season 8. ([Inverse, Fortnite Season 8 stole the Apex ping system, 2019](https://inverse.com/article/53705-fortnite-season-8-apex-legends-ping-system))
- A competitive Apex guide treats pings as the baseline channel because they work without voice, survive a teammate muting, and leave a text trail in chat (one ping produces world marker, voice line and log line together). (search summary of [Guild Order, Apex callouts and comm grammar, n.d.](https://guildorder.com/games/apex/guides/callouts-and-comm-grammar))
- Counterpoint: when Rainbow Six players asked for an Apex-style ping wheel, Ubisoft argued that if players could ping everything, communication would decrease further. (search summary of [Mein-MMO, Rainbow Six will Pings von Apex Legends, n.d.](https://mein-mmo.de/rainbow-six-will-pings-von-apex-legends/))
- A GDC level design workshop lists waypoints, HUD markers, buddy callouts, cutscenes and forced camera moves as ubiquitous guidance aids and asks whether that guidance can be done through blockmesh and lighting instead. ([GDC Vault, Level Design Workshop: Invisible Intuition, n.d.](https://gdcvault.com/play/1025529/Level-Design-Workshop-Invisible-Intuition))
- Arc Raiders patch 1.22.0 added a console HUD visibility mode with options including "Crosshair Only" and "Hidden", handing message volume control to the player. (search summary of [Arc Raiders, Patch Notes 1.22.0, n.d., likely 2026](https://arcraiders.com/news/patch-notes-1-22-0))

### Inferences
- Rule of thumb for a top-down shooter: if the information has a position in the world (enemy, loot, threat direction, extraction point), put it in the world (marker, ring, edge arrow, positional sound) and do not also write it; if it is a state change with no place (extraction closing, teammate downed off screen), use a short text callout plus a distinct sound; if it is a running number (money, score), use an icon counter that ticks, not a new line per gain.
- One event should drive several redundant cues from one place (the Apex ping model: marker, voice, log line), so the manager can drop the text and keep the marker when the text channel is busy.
- Rumble (pad) is a fit for P0 danger only; using it for rewards trains players to ignore it. This is an inference; I found no source on rumble as a notification channel.

### Gaps
- No source found on controller rumble as a notification or alert channel in shooters.
- No source found that measures the effect of replacing text with icons or sound (for example comprehension time).

## 6. GDC talks, blog posts or postmortems on cutting message volume, and the result

### Takeaway
I found no GDC talk or postmortem that reports cutting HUD message volume with measured results. The only concrete recent examples are patch notes: Call of Duty: Modern Warfare 4 reduced guide-character notifications (October 2026), Enshrouded's 1.0 patch made camp alerts "less spammy", and Arc Raiders added HUD-hiding modes. None states results.

### Cited Findings

### Inferences
- The industry pattern visible in patch notes is to cut volume after launch in response to players (guide notifications, alert spam) and to give players a HUD hide option. A notification manager that logs every message it shows, merges and drops would let a small team find its own "Gunny" before players do.

### Gaps
- No GDC Vault talk found that is specifically about reducing notification or message volume, with before and after data. GDC Vault search and video pages require a login, so a targeted Vault search (terms such as "HUD", "notification", "feedback", "announcer") could still find one.
