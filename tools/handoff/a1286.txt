| RESTORING FROM A FILE REBUILDS THE SCREEN INSTEAD OF HALF OF IT | v12.86 | Finding 2 of the 2026-09-11 read-only audit, and bigger than the audit said. The audit found that restoring a backup from a file never re-applies the stash layout, so the Settings row prints the restored number over a grid still drawn in the old one and they disagree until he happens to reload. That is one of at least five: boot has a block that runs once the profile exists and it does five things, the saved zoom, the stash layout, the game options, the menu zoom and the contracts, and the restore path runs none of them, calling renderHub and renderSettings and stopping. Boot already learned this once at v8.15 for the stash layout alone, with a comment saying his saved choice was silently thrown away every boot; restoring is the second place a whole profile arrives and never got the same treatment. So the fix is not a fifth call, it is the reload its two siblings already do: the friend restore-code path has reloaded since v11.04 and the UNDO button added at v12.85 reloads, so the file path was the odd one out and adding applyStashLayout would have closed the one symptom the audit looked for and left the other four. It is one place now rather than three: every profile-replacing path ends in finishRestore, which re-draws, says so, and arms the same cancellable reload the v11.04 path uses, RESTORE_RELOAD and RESTORE_TIMER being that path's own handles written so anything driving a restore can see it coming and call it off. Check 12.86 requires one shared finish, calls it and requires the reload armed rather than fired with a real handle to cancel, then presses UNDO and requires the same arming; that press is the control and on the v12.85 fixture the flag stays at 0, failing with both arms rather than skipping. NOT MEASURED: a script may not put a file into a file input, so the path the audit complained about cannot be pressed from a check; what is asserted is that all three paths end in the one finish that arms the reload, not a click through the picker; and it does not prove the page comes back correctly after the reload, which is boot's job and what the rest of the corpus exercises |
