## v13.21 - THE LAST RESORT FOR A RUN REPORT SAYS WHETHER IT WORKED

WHERE A FAILED COPY SENDS YOU. On itch the game runs in an iframe. v13.20 stopped
the report claiming a file download there and pointed the player at Copy report.
The outcome card's Copy report has handled a refused clipboard honestly since
v11.32: when every route fails it says the report is under Settings, Recorder.

AND THE RECORDER COPY BUTTON SAID NOTHING, EVER. It selected the text, called the
async clipboard with no rejection handler, and returned. Copied, blocked and
refused all looked identical. So the one place a failed copy directs a player was
the one place that could not tell him whether it worked, and on itch, with no
collector deployed, that button is the last way a friend's run reaches Daniel.

THE LEGACY COPY GOES FIRST, WHILE THE CLICK IS STILL LIVE. A copy command needs
the user's gesture. By the time an async clipboard promise has rejected, the
gesture is gone, so a fallback that waits for the rejection runs at the moment it
is least likely to work. The text is selected, the command runs immediately, and
the async clipboard is only the second try.

WHEN BOTH FAIL, THE REPORT STAYS SELECTED AND HE IS TOLD TO PRESS CTRL+C. A
selected textarea can be copied by hand inside any frame. That is a path nothing
can block, which is what a last resort has to be.

REPRODUCED WITH CHECK 11.32'S OWN INSTRUMENT: the clipboard hidden with
defineProperty and the copy command stubbed, which keeps every branch synchronous
so the corpus runner can read the result. On v13.20 the button text does not
change whether the copy succeeds or is refused.

NOT BUILT, RECORDED FOR EVIDENCE: the outcome card's own Copy report still tries
the async clipboard before the legacy command, so on itch its fallback also runs
after the gesture has expired. That cannot be reproduced without a real click
inside a real cross-origin frame, and that code is guarded by checks 11.32 and
11.65. It waits for a friend's report rather than for a theory.

Not verified: the async rejection branch itself, which the synchronous instrument
cannot reach, although it calls the same failed() the tested arm does; and the
real itch frame, which is still behind his password.
