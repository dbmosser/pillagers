## v15.78 - IN A SAME MACHINE MODE, WORLD SOUND COMES FROM ONE WINDOW ONLY

His order of 2026-09-25: native multiplayer, played first as two players on the SAME PC in two game windows on two screens,
player 2 on a controller. This is phase 1, build 5 of tools/multiplayer/plan.md (section E) with the corrections in critique.md.
The problem this build solves: two windows on one PC both play the world sound (the Undercroft ambience, the music, the
footsteps, the blips) through the same speakers, a few milliseconds apart, so everything is heard twice with a smear on it.
Player voices are not part of this build.

WHERE THE MUTE SITS. The game reaches the speakers through exactly three nodes, and nowhere else (every .destination in the
file): BUS (bus(), the shared output every sfx, blip, machine voice and the ambient bed connect to, which also feeds the room
reverb send), the reverb's wet return (verb(), REV.wet) and the music's lowpass (tickMusic(), MUS.lp; the music is dry, by
design, and never on BUS). The fourth .destination in the file, blip's OUT=bus()||a.destination, is a fallback that can only
be taken when there is no context at all, so it is left alone. Those three lines now connect to netSndOut(a): in a same
machine mode (NET.same set) one master gain, NET.sndG, made on first use per context and connected to a.destination; outside
the modes a.destination itself, so no node is added and the chain is what v15.77 had. A window switched OFF sets that gain to
0 and nothing else: every oscillator, buffer, ramp and scheduled note keeps running behind it, the context clock keeps
counting, the music scheduler keeps filling its window, so switching back ON is instant and in step with the other window.
Never AC.suspend: a suspended context stops its clock, and the music would come back mid-bar and out of step (the
visibilitychange handler that suspends a hidden tab is untouched; a visible window that is not in front is not hidden).
The fixture overrides say, sfx and blip at the source (mkfixture), so the mute sits below them, at the output. The menu
blips go through it too: a menu click plays the same 'pick' voice a pickup does, through BUS, so there is no clean way to
leave the blips audible in a window switched off; it is silent, and the PARTY window says so.
THE HOST already plays frames on the title before it picks the mode (tickVerb and tickMusic run every frame from load), so
its three nodes may already sit on the destination at the pick; netSndRoute moves them behind the gain once (disconnect from
the destination, connect to the gain, a marker on the node so a second pick does nothing), leaving the BUS feed to the reverb
send in place. The player 2 window sets NET.same at boot, before any node exists, so its nodes are made behind the gain.

THE SWITCH. THIS WINDOW: SOUND ON or SOUND OFF, a row in the PARTY window (#partysnd, #partysndbtn, #partysndnote) under the
CONTROLLER row, shown in a same machine mode only; a press flips it (netSndToggle). The host defaults to ON, the player 2
window to OFF (netSndDefault); the choice is kept under salvagerun:samesound:host or :p2 ('1' or '0'), beside the pad pick and
not in the profile, so saveProfile is untouched; and it is told to the other window as {t:'snd',pair,on} at the host pick
(netSamePick, netSndInit after netPadInit), at the player 2 boot (netSameBootP2, before ready, so ready stays the last word
of the boot as checks 15.76 and 15.77 read it), again when a ready arrives on the host (a reloaded player 2 window), and on
every change; the receiver keeps it on NET.sndOther (-1 not said) and the note reads: Press to change. The other window:
sound on / sound off / not said yet. Two windows on one PC play the same world sound twice, so one of them is switched off. A
window switched off keeps every sound running and comes straight back when switched on. END THE PARTY (netSameStop, via
netReset on the host) puts the gain back to 1 and forgets the other window's word (netSndRelease); the node stays, at 1,
which changes nothing. A player 2 window keeps its mode and channel across netReset as before, so its switch stays. The
player 2 title line adds: World sound plays from the player 1 window; the SOUND row in the PARTY window switches it. No word
on the row that controller B looks for (leave, close, back, done, return).
- NET gains sndOn, sndOther, sndG, sndAc. The ?netslot and ?p2 test handle window.__net gains snd() (on, other, gain as the
  node holds it or null, routed, ctx, state, kept) and sndSet(on), for tools/nettest.html.
