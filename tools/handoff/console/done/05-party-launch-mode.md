The game has no address option for a party: grep location.search finds only the ?netslot / ?p2=1&mode=coop&pair=..&arc=1 readers (netSlotOf, netP2Of, netModeOf, netPairOf, netArcOf). EVERYTHING BELOW IS GATED ON ?party=1 IN THE ADDRESS. Without it nothing changes, byte for byte, and the seed 4242 fingerprint holds.
1. HOST WINDOW  <game>.html?party=1&pair=CODE   (CODE is [a-z0-9]{4,16}, read like netPairOf). At boot, before the first paint, skip the title (hide #title) and do what arcadePick does WITHOUT window.open (the shortcut opens player 2 itself): NET.pair=CODE; NET.arcPick=1; NET.mode='coop'; NET.same='host'; netStartHost(); netSameChan(); netPadInit(); netSndInit(); netSameHostLink(); then the start function the title row runs (NET.start()) and arcadeEnter('host'). With no &pair the window makes its own and falls back to the plain title row (click opens player 2 as today).
2. PLAYER 2 WINDOW  <game>.html?p2=1&mode=coop&arc=1&party=1&pair=CODE  (the first four words are read today). With party=1 it never shows its title ("Enter the Undercroft"): show the arcade attract at once ("Player 2: press A") or one plain waiting line until arcon arrives.
3. RE-LINK WITH NO TOUCH: after a reload of EITHER window (a crash, F5) the pair finds itself within 10 s. Today player 2 posts {t:'ready'} only at its own boot and the host answers; if the HOST reloads, nothing tells player 2 to speak again. Fix: the host posts {t:'hostup',pair} at every boot and every 5 s while nobody is linked; a player 2 window that hears it answers {t:'ready'}, and the existing handshake follows (arcon, offer, answer, arcjoin). Both reload paths run arcadePadsIn again.
4. CAREER AND THE STASH OUT OF REACH, even after a crash: with ?party=1 no screen outside the arcade can be reached. The title shows none of: 1 PLAYER, the co-op row, the saves panel, CREATE A NEW SAVE, ENTER THE UNDERCROFT, the stash, trader, Mainframe, character select, leaderboard. If the arcade is left for any reason except the operator's Exit demo (a caught error, arcoff, anything that calls arcadeLeave), the page reloads straight back into the party attract (location.reload keeps ?party=1) and never shows the title. The operator card's "Exit demo" (Ctrl+Shift+F10) with ?party=1 goes to the same address WITHOUT ?party (the full title), so only the operator can get there. The pause menu stays as it is (Resume, Settings, Feedback, What's new, End run): every setting is reachable (Q30), and no operator volume or end-run controls are added (Q31).
