| THE FEELING TAG FOR THE TACTICAL BELT CALLS IT THE TACTICAL BELT | v12.90 | Finding 4 of the 2026-09-11 read-only audit. His vocabulary is binding, the rename was announced outright in the release notes, and the game keeps it everywhere else: the pause key list, the stash heading, the loadout label, the keyboard and pad legends. The feeling-tag button was the one place it was missed, and it is the single most-seen piece of player-facing text in the run-report slice. It reaches HIM and not just the player: tap the tag, press LOG RUN AND RETURN, and the string is stored on the run, printed on the Undercroft run row, and lands in the report twice, in the FEELING TAGS header and under the run itself, and that report is the file a friend copies out and sends to Daniel. The lint provably cannot catch this one, which is worth knowing before anyone trusts a green lint run on vocabulary: the word is on its banned list, but its sweep only considers quoted strings of 30 to 400 characters and this one is 18, so the sweep never offers it the string and a green vocabulary lint means nothing about short labels. Old runs store the literal, so renaming the button alone would leave every run already logged printing the retired word for the rest of the profile life; a display-time map carries them forward instead of a migration, so nothing stored is rewritten, an export he already has still reads the same way, and there is no one-shot stamp to get wrong, which is its own defect class and cost a build at v12.43. Check 12.90 requires the retired word absent from the tag set the card draws and the new name present, then plants a run holding the old string and requires the run row, the FEELING TAGS aggregate and the per-run report line all to show the new name while requiring the stored value to still be the old one, so a display map cannot have quietly become an unstamped migration; the control is a tag that was never renamed, because a map swallowing anything it did not recognise would pass every arm above; every needle is assembled so the row cannot be found by its own search; four arms fail on the v12.89 fixture. The new name is nine characters longer and that was checked rather than assumed: tagwrap is a wrapping flex row with a 560px cap and a 6px gap, so a longer label reflows onto the next line instead of overflowing, and no layout change was needed. NOT MEASURED: it reads the tag set and the built report rather than clicking the button on the card, which the v11.01 check already covers; and the reflow is read off the stylesheet rather than measured in pixels, because the tag row only exists while the outcome card is up |
