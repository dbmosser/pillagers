- P1 DEAD CONTROL: a throwable put on a tactical belt key is a dead key AND it deletes the working grenade cell. Raised independently by two regions. A throwable lives in G.pouch and never in G.bag, so `have` is 0 at 13016 and the assigned cell falls through the kind ternary at 13028 to 'item'; hotGun at 14267 treats 'item' as a held gun, so the trigger fires your rifle under a caption reading "[FIRE] use" (22569), useHot returns at the bag test (13131) so the use key does nothing, the cell draws x0 greyed while the pouch holds two, and the dedupe at 13051 blanks the derived 'throw:'+tk cell. Bind all three and no path reaches doThrow or startCook for the whole raid. Hidden in the Undercroft, where hubBagState (25648) counts P.kit. It is the v8.31 stim hole, one item type later, four lines under that comment. SHIPPING as v11.59.
- P2 WRONG STATE: going down mid-cook freezes the fuse for the whole bleed-out. damagePlayer's down branch (11987) clears p.prep and not p.cooking, and the downed branch returns above both the cook clock (14276) and the release (14340), so the world readout paints a static "COOKING 0.6s" over the body and the v11.55 shout can flash permanently at a player who cannot throw. On revive the first button-up frame runs releaseCook and hurls a live frag at the cursor with no input, carrying the frozen fuse; if the button is still held the cook resumes and can go off in the hand of a man just stood up at 40 hp. FIX: clear cooking, cookT and cookKind beside p.prep=null, as killPlayer already does at 11875. (The roll branch freezes it too but self-recovers.)
- P2 WRONG STATE: Q cycles a hidden selector, so the belt highlights one throwable and the trigger throws another. cycleThrow (11296) writes only G.tsel; every belt display reads G.hot; the trigger reads G.tsel. The game's own gear card states the rule this breaks: "TACTICAL BELT, 1-9 selects, FIRE uses it" (24288). The cost is a grenade you did not mean to spend, not a blind self-frag, since the cook label names what is in hand. Q is also in neither controls legend. FIX: make cycleThrow move the belt selection through setHot, which already syncs G.tsel at 13111.
- P2 WRONG STATE: standing in a SECOND open extraction ring hijacks the pointer. tickExtractTick's `if(z&&z.open) G.active=z;` (13261) has no beacon test, so while you stand in a second open ring the banner names it as the inbound one, the centre of the screen offers HOLD E TO EXTRACT over a ring with no ship, holding E starts a fresh call there while your real ship departs, the approach pings and the last-eight-seconds warning go silent, and a downed player has the surrender refused because giveUpTick (13893) measures against the wrong ring. Reachable with no deliberate double-call, since an AI pillager can call a ring itself (17137). FIX: never re-point G.active away from a ring that has a live beacon.
- P2 WRONG STATE: the storm's FULGURITE cache glows the rarity of the loot it threw away. mkContainer stamps best from the cache roll it made, and line 5156 replaces ct.loot with the strike's own item without recomputing it, so the pulse colour describes discarded loot on roughly half of all fulgurites. FIX: use setLoot, which draws nothing from the seeded stream.
- P2 TEXT vs CODE: with the raid clock set to OFF the boarding window is 3 seconds, not 30. z.hold=Math.min(30,Math.max(3,G.timeLeft-1)) with timeLeft pinned at 0 (13776). The game prints the real 3, so it does not lie on screen, but the pull line still says "The raid clock runs out first" (13364) in a raid with no clock. FIX: do not derive the window from a clock that does not exist.
- P3 WRONG STATE (developer-facing): a PINNED weather leaves the turn timer permanently expired, burning 13 seeded rolls every frame from the first expiry onward (5083). Nothing a player sees changes, but a pinned raid stops being reproducible from its seed, which is the rule stated four lines above pickWeather. FIX: reset G.wxAt on the no-change path.
