## v15.83 - THE SECTOR MAP NEVER SITS OVER THE OPEN STALL

Trade audit finding (MEDIUM), entry 1 of the confirmed list.

Walk up to the Peddler, press E so the stall panel is up, and press M. In raidKey the map toggle, if(code==='KeyM'&&G&&
!G.over&&!repeat){ G.mapOpen=!G.mapOpen; }, sits above the open-stall block and had no stall test, so the map opened. In
render the stall is drawn early (if(G.trade) drawTrade();) and the map last (if(G.mapOpen) drawMapOverlay();), and
drawMapOverlay begins by filling the whole screen at .94, so the stall vanished behind the map while it still owned the keys.
ESC then went to the stall block, which runs before the v12.89 map line, so the hidden stall shut and the map stayed up; TAB
goes through backOut, which tests G.trade before G.mapOpen, so it did the same. The digits still belonged to the stall: 1 ran
pedSellAll and sold every eligible backpack item at the stall rate behind the map, with the panel unseen, and 2 to 9 bought
stock. The other way in was open too: nothing in updatePlayer read mapOpen (its only mapOpen line is the downed reset), so E
with the map already up opened the stall underneath it, and pad X does the same because padHold turns it into KeyE. On a
controller M itself could not do this: the stall branch in pollPad (v13.49) returns before the D-UP toggle. Nothing marks the
stacking as deliberate; the v15.35 note that the map comes first describes the mouse handlers. Not a TXSHIP key, not balance.

THE BUILD. Two edits, the finding's own fix. The M toggle in raidKey carries !G.trade, so a fresh M while the stall is open
does nothing (it falls through the stall block, which does not name M, to the preventDefault list, and nothing further down
answers M). The stall-open line in updatePlayer reads G.trade=ped; G.mapOpen=false; mouse.down=false; blip('pick');, so
opening the stall, by E or by pad X, shuts the map in the same frame, the way the downed screen clears it (v14.07). Those are
the only two places that set mapOpen true apart from the pad D-UP toggle, which cannot run while the stall is open, so no path
leaves the map over the stall. No number, no dial, no loot table and no word of player text moved, and map building is not
touched, so the seed 4242 fingerprint in __verifySafe cannot move.
