| THE GAME TELLS YOU WHEN A FOUND GUN CHANGES YOUR HANDS | v12.73 | 2026-09-08 first-hour audit, confirmed by a skeptic and then by me reading the loot grant and the message function end to end. The message line holds exactly one string, writing the text and a 3.2 second clock, so the last thing written in a frame is the only thing seen. The loot grant writes two lines inside its per-item loop, both about which gun is now in which hand: one for a gun going into an empty slot, naming the key that swaps to it, and one for a gun that replaced what he was holding, with the damage difference. Then, after the loop, it writes the Found line over the top, guarded on the list of things taken being non-empty, which is true whenever the loop ran at all: so this was never an occasional collision, it happened on every pull and neither line has ever been readable. It is not decoration, because a brand new character deploys with an empty second gun slot, so the first decent gun a first-time player pulls arms slot 2 and puts a live number key under his finger while the game tells him only the name of the item. The per-item line is kept rather than spoken now, and the one line spoken carries both facts: a single gun says the gun line alone, since the summary would only repeat the name it already contains, and a gun with company says the gun line and then the list. Check 12.73 deploys a real raid, empties the second slot the way a new character has it, drives the real grant and reads the one line he is left holding, with a control that a pull containing no gun still says exactly the plain found line; fails on the v12.72 fixture. NOT MEASURED: it reads the stored message rather than pixels; two guns in one pull still leave only the second gun's line, which is the same last-one-wins rule as before; and whether the longer line is comfortable to read in a firefight is his judgement |
