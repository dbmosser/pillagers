## v11.96 - FIRST TEN MINUTES: DYING WITH THE FREEBIE KIT KEEPS THE PISTOL YOU OWN

From the 2026-09-06 read-only audit of a new player's first ten minutes.

THE FINDING. The FREEBIE KIT issues a Scav Pistol. By his v6.88 spec an
extraction keeps it, so the issued pistol is deliberately not flagged as
issued (issued kit is never banked). On a death the outcome card walks the
guns in hand and, for each one whose id is in the armoury list, deletes it
from that list and prints LOST. It went by id alone. A fresh profile owns
exactly one gun, a Scav Pistol, so a friend who took the freebie kit on his
first run and died had his own pistol, the one that never left the
Undercroft, deleted from his armoury and priced into the loss line. The
pickup path fixed this same fault for field-found guns long ago by keeping
provenance on the weapon slot; the death path never learned.

THE BUILD. The death splice asks the slot whether the gun came out of the
armoury (the same wepFromArmory and secFromArmory flags the pickup path
reads, carried through swaps), and only then removes it from the list. A
field-found gun no longer touches the armoury on a death either. The free
kit's pistol, not from the armoury and carrying the free kit's gun id in a
free-kit raid, is out of the ledger entirely, as an issued loaner already
is: not counted, not priced, no LOST line, so the count and the lines
agree, which is the v10.72 rule.

MEASURED. Check 11.96 sets the profile to own one pistol with the free kit
chosen, starts the raid the way the lift does (commitKit, then startRaid;
the harness deploy clears the free kit flag before it builds, which the
review caught), confirms the issued pistol is in hand, ends the raid by
death, and requires the pistol still owned and the card counting no gun
lost. On the v11.95 fixture the armoury comes back empty.

Not verified: an extraction with the free kit, which still sets the issued
pistol as the equipped gun (the audit's separate medium finding, queued);
his own reading of the card.
