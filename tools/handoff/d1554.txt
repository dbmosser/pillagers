The button keeps the packing aside, P.kitSaved={kit:(P.kit||[]).slice(),hot:...}, and then sets P.kit=[] (v12.16), and the

THE BUILD. One edit, spendHeld, the corrected fix from the audit verdict. When P.freeKit is set and P.kitSaved.kit is a list, the
copies of that item on the set-aside list are counted as packed, capped at what the stash holds beyond P.kit's live packing (the
same test freeKitRestore makes, so a set-aside list longer than the stash is not over-counted). Loose copies still go first
(v13.59). Any set-aside copies still needed come off the set-aside list from the end, and once none of that item are left on it,
a set-aside belt key bound to that item is let go, the way clearKeysFor does for live packing (dropDeadKeys still runs in
freeKitRestore). With no freebie kit taken, or no set-aside list, the old path runs unchanged: unpackSome on P.kit. The return
value is the number of packed copies used either way, so buildRack, the bench, SLOT A DATA CORE and Arm name them with their
existing sentences, and askKit's raw count now matches what freeKitRestore gives back. The Stash grid is greyed and takes no
pointer while the freebie kit is on, so P.kit stays empty there. No player text was added or reworded, no TXSHIP key touched, and
no number, dial, loot table or seeded draw moved. The map build is not touched, so the seed 4242 fingerprint (ents 85/374,
containers 165/593) cannot move.
