## v15.56 - A DOOR KEY IS NEVER HIDDEN IN THE VAULT CASE OR BEHIND ANOTHER LOCKED DOOR

Keys audit finding 4 (LOW).

Every locked room is promised one key on the map (v1.75): the guarantee in buildRaid looks for a copy of the key outside the room it
opens, and if there is none it pushes the key into a random container from a list that leaves out caches, the strongbox and boxes
inside THAT room. Two kinds of box it must never use were still on the list. THE VAULT CASE (v4.40) is built just above the
guarantee as type jackpot with no cache flag, so it was a legal pick. LOOT.jackpot has no KEY, so a key in the case can only come
from here, and his v4.40 answer says the case is not on the map and not marked; with a Data Core burned, startRaid lists every box
holding a key_ item and the sector map drew KEY on it. The finding estimates about one raid in 70 to 80 (not measured). And outside()
only tests the room this key opens, so an ordinary crate, locker or safe standing inside a DIFFERENT locked room was legal too: the
v2.12 reach pass leaves those in place on purpose (49 across 20 maps). The door then needs a second key first and nothing says so,
and if two rooms' keys land in each other's rooms neither door opens unless a spare key rolls or the Peddler stocks one. The
verdict found the same hole in the have test: a KEY that rolled naturally (LOOT.safe or LOOT.cache) into a safe or cache inside
another locked room counted as the promise kept, so no reachable key was placed.

THE BUILD. Three edits inside the guarantee IIFE, all existing comments kept.
1. sealedAny(CC), defined once before the room loop: true when the box is within 40 units of ANY locked room, the same 40 unit test
   outside() uses for one room.
2. The have test now records two answers in the same pass: have, any copy outside this room (the old answer), and haveOpen, a copy
   clear of every locked room. Only haveOpen skips the room.
3. The candidate list and the single ri(0,cands.length-1) draw are exactly as before. If the drawn box is THE VAULT CASE or
   sealedAny, the pick walks forward through the same list, wrapping, to the next box that is neither. When have was true (the old
   code took no draw at all, because a copy behind another door satisfied it) no draw is taken now either: the walk starts at
   (seed>>>0)%cands.length, buildRaid's own seed. If no box on the list qualifies, no key is placed, as when the list was empty.

WHY NOT THE VERDICT'S correctedFix AS WRITTEN. It filters the jackpot and every sealed box out of the list BEFORE the draw. A shorter
list turns the same drawn number into a different box, so on seeds where the old key already sat in a perfectly good box it would
move, and on the seeds where a natural key sat behind another door it adds one ri draw and shifts everything drawn after it. Both
break the seed fingerprint rule. This build does the same thing for the broken cases and nothing at all for the rest: on every seed
the guarantee takes the same draws in the same order, and every key the old code put in an open box stays in that box. Only a key
the old code put in THE VAULT CASE or behind a locked door, or never placed because of a sealed natural copy, lands somewhere new.
Nothing after the guarantee reads which box holds a key until startRaid builds G.intelKeys (checked: no later line in buildRaid
draws from container loot or best), no container is added or removed, and no loot table, number, dial or player text moved, so the
seed 4242 counts (ents 85/374, containers 165/593) cannot move. If seed 4242 was itself one of the broken cases on either map, a key
there moves box; the counts still hold.

MEASURED. No browser. The old and new guarantee blocks were cut out of the real file and run side by side in JScript (cscript) over
6000 synthetic layouts with 1 to 4 locked rooms, up to 43 boxes, a quarter of them set inside a room, caches, strongboxes, natural
keys in 12 percent of boxes and a Vault Case sometimes inside a room, far more broken cases than a real map has: draws taken and the
RNG state after were identical in all 6000; 11566 keys the old code put in an open box stayed in exactly that box; all 2554 broken
old placements (1032 of them the sealed natural copy) went to a box clear of every room and not the case; and whenever a legal box
existed every room had a copy clear of every room.
