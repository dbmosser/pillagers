## v15.53 - SLOT A DATA CORE SAYS WHEN IT TAKES A PACKED CORE OUT OF THE BACKPACK

Rack audit finding (LOW).

At the Stash, pack your only Data Core into the backpack (drag it in, or Equip). Packing leaves the item in P.stash, so THE
MAINFRAME RACKS tab still says "One is in the stash." and SLOT A DATA CORE is live. Press it: "Core slotted. Your next ascent
carries intel." slotCore spliced the first core out of P.stash with no look at the packing, so with every core he held packed
the backpack lost its core with no word. P.kit still named it until stageKitLive next read it and trimmed it quietly, and a belt
key bound to the core stayed pointing at nothing until dropDeadKeys ran after a raid. BUILD A RACK, two buttons up in the same
tab, has spent through spendHeld since v13.59 and named the packed parts it took out of the backpack since v15.18. With a loose
core left over the old splice did no harm, because the packed copy stayed live. The Arm button on the Intel row of the ascent
check (renderStage) had the same bare splice.

THE BUILD. Two edits, both the corrected fix from the audit verdict.
1. slotCore: P.stash.splice(ix,1) becomes var _cp=spendHeld('core',1). A loose core goes first (the v13.59 rule); only when
   every core is packed does spendHeld call unpackSome, which takes the core off P.kit and, through clearKeysFor, lets its belt
   key go, and then the stash copy is spent. The core line is unchanged and one sentence is added after it when a packed core
   was taken: "Used 1 packed Data Core out of your backpack.", the same words BUILD A RACK uses. One toast, because a second
   would write over the first.
2. renderStage, the Intel row: the Arm handler spends through spendHeld the same way, and when it had to take a packed core it
   says "Used 1 packed Data Core out of your backpack." through say2, the Undercroft answer line the rest of that screen uses.
   No route opens the ascent check today (every way up goes through ascendNow since v6.18, and nothing adds on to #stagemodal),
   so this edit only keeps the two ways to spend a core one rule.
"Core slotted. Your next ascent carries intel." is not a key in TXSHIP, and no sentence in TXSHIP was reworded; the new
sentence is new text. No number, no dial, no loot table and no seeded draw moved. The map build is not touched, so the seed 4242
fingerprint (ents 85/374, containers 165/593) cannot move. The v14.99 core hint and the button label are untouched.
