## Gate a draft: gate.sh KEY [--base REV] [--draft FILE] [--recent N]
`tools/cloud/gate.sh KEY` reads `tools/handoff/drafts/draft-KEY.json` (title, why, now, edits, check) and does what
`tools/handoff/shipone.sh` + `gen-draft.ps1` + `dryrun.ps1` + `gate.ps1` + `recent.ps1` do, on copies only:
1. gen (gate.py): apply the edits to the game at REV (default HEAD), VER bump, DEVNOW `now:` line, and insert the check above
   the previous version's check in a copy of mkfixture.ps1. An anchor must match exactly once (whole lines, CRLF tolerant);
   all text must be ASCII; `v16.xx` in a replacement becomes the new version (as gen-draft does). New version = base VER + 0.01.
2. parsecheck on the patched game.
3. the new check PASSES twice on the new build.
4. the control: the same check FAILS (not SKIP) on the previous game, built with the same patched fixture.
5. recent: the newest N (default 80) older checks, on the new build and on the control. STOP if one fails on the new build and
   passes on the control. Checks that fail on both (the known always-red set) are not counted.
6. __verifySafe holds the seed 4242 fingerprint. 7. `node --check` of the patched script.
Ends with `PASS v27.31 (KEY): total 240s` or `STOP v27.31 (KEY): reason`. Exit code 0 only on PASS. It writes
`tools/fx0dry-KEY.html` and `tools/fx0ctl-KEY.html` (gitignored by `tools/fx[0-9]*.html`, deleted at the end unless GATE_KEEP=1) and
`/tmp/pillagers-gate-KEY/` (dry.html, prev.html, patched mkfixture.ps1, recent and verify output). It does not commit or push.
HEAD is the base, so gate against a fresh `git pull` of master; if master moved, the draft's anchors may not match: that is a STOP.
Applying a PASSED draft is a separate step on the PC (its own ship lock); this gate is advice, not a ship.

`tools/cloud/smoke/draft-pickrows.json` is the v27.14 change rebuilt from p2714/f2714 (its draft file was never committed):
`tools/cloud/gate.sh pickrows --draft tools/cloud/smoke/draft-pickrows.json --base a7dd947` must PASS (a7dd947 = v27.13).
gate.py's output for it is byte for byte the shipped v27.14 game and fixture.

## Corpus: corpus.sh [FILE] [SHARDS] [OUTDIR]
`tools/cloud/corpus.sh fixture.html 3 /tmp/corpus` runs every __REGRESS entry once, 3 shards in parallel (4 cores; more
shards time out). A check that stalls (CHECK_MS, default 120 s) is named as `TIMEOUT at index N`; the shard restarts at N+1 on a
fresh page. Rerun any red alone before believing it: `node tools/cloud/run.mjs seq fixture.html I I+1`.
Results of the first run: tools/handoff/research/cloud-corpus-<date>.md.
